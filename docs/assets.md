# CATZ vs DOGZ — специфікація ассетів для дизайнера

Технічне завдання на всю графіку (і, окремим розділом, звук) для гри
`catz-game-v2`. Розміри виведені з коду гри — їх треба дотримуватись, інакше
ассет не збігатиметься з фізичним хітбоксом.

## 1. Технічний контекст (обов'язково прочитати)

| Параметр | Значення |
|---|---|
| Ігрове полотно (ТВ) | **1280×720 логічних px**, розтягується на весь ТВ (FIT) |
| Цільові екрани | ТВ 1080p/4K через AirConsole + телефони (контролер) |
| Масштаб експорту | **всі растрові ассети екрана — у 2×** від логічного розміру (гра на 1080p не милить). У специфікації вказано: `логічний розмір (експорт 2×)` |
| Формат спрайтів | PNG-24 з альфа-каналом (RGBA), без інтерлейсу |
| Формат іконок контролера | SVG (телефони мають DPR до 3×; SVG завжди чіткий і легкий) |
| Анімації | спрайтшит із рівною сіткою кадрів (усі кадри одного розміру), без відступів між кадрами |
| Іменування | kebab-case латиницею: `cat-ginger.png`, `block-stone-damaged.png` |

**Стиль: ЗАТВЕРДЖЕНО — HD-картун** (рішення Каріни, 2026-07-11): намальовані
персонажі/блоки, експорт 2×, розміри як у цій спеці. (Альтернативу
піксель-арт розглянуто і відхилено.) Вся спека написана під цей стиль.

**Куди здавати:** структура папок у грі —
```
public/assets/
├── characters/   (спрайтшити персонажів)
├── blocks/       (текстури блоків будівель)
├── env/          (фон, земля, декор)
├── ui/           (логотип, банери, прев'ю структур — екран ТВ)
├── icons/        (SVG для телефона-контролера + іконки зброї)
├── fx/           (частинки, вибухи)
└── audio/        (звук — окремий виконавець, розділ 8)
```

## 2. Персонажі — 8 штук (4 коти + 4 собаки)

Зараз у грі 3 тимчасові спрайтшити, перефарбовані тінтом. Потрібні **унікальні
персонажі** — це головний обсяг роботи.

### 2.1 Розміри і прив'язка (критично)

Фізичний хітбокс персонажа — капсула **36×48 px** (логічних). Художній силует
може трохи виходити за хітбокс (вуха, хвіст), але:

| Правило | Значення |
|---|---|
| Кадр спрайтшита | **64×64 логічних px (експорт 128×128)** — запас під вуха/хвіст/анімацію |
| Ноги персонажа | стоять на **нижньому краї кадру, по центру** (pivot = bottom-center) — інакше персонаж «літатиме» над блоками |
| Тіло (без вух/хвоста) | вписати у 36×48 px по центру-низу кадру |
| Максимальна ширина силуету | ~56 px (персонажі стоять на сходинках 40 px завширшки) |
| Напрям погляду | **всі дивляться ВПРАВО** — собак гра віддзеркалює автоматично. Увага: асиметричні деталі (пляма на оці, шрам) у собак з'являться дзеркально — або уникати асиметрії, або погодити |

### 2.2 Список персонажів

Кольори — орієнтир з ігрового конфіга (можна відходити, зберігаючи впізнаваність
команд: коти — теплі/помаранчеві акценти, собаки — холодні/сині).

| `cat-fisher.png` | Fisher Cat | 🐱 | рибалка (вудка/капелюх), фішинг-бомба |
| `cat-fat.png` | Fat Cat | 🐱 | товстун-важка артилерія, смердюча бомба |

### 2.3 Анімації (кадри в одному спрайтшиті, зліва направо рядами)

Пріоритет 1 (без цього гра не збирається на нову графіку):

| Ряд | Анімація | Кадрів | Примітка |
|---|---|---|---|
| 1 | idle | 4 | дихання/помахування хвостом, зациклена |
| 2 | throw (кидок) | 4 | замах → кидок; момент вильоту снаряда — 3-й кадр |
| 3 | hurt | 2 | отримав шкоду (гра зараз блимає прозорістю — замінимо) |
| 4 | dead | 1 | поза «в ауті» (хрестики-очі), НЕ зникає з екрана |

Пріоритет 2 (полірування): victory (4 кадри, радіє), fall (1 кадр, летить).

Разом на персонажа: спрайтшит 64×64 лог. px на кадр, сітка 4 стовпці × 4–6 рядів
→ файл **512×512 (2×)** для P1. Тобто P1 = 8 файлів по ~512×512.

## 3. Блоки будівель — 3 матеріали

Будівлі складаються з фізичних прямокутних блоків **різних розмірів** (нижче —
всі розміри з коду). Малювати окремий PNG під кожен розмір не треба: потрібні
**текстури, що тягнуться**, + стани пошкодження.

### 3.1 Фактичні розміри блоків у грі (логічні px, Ш×В)

| Матеріал | Використання | Розміри у блупринтах |
|---|---|---|
| **stone** (камінь) | фундаменти, дахи | 58×36, 48×32, 70×36, 98×30, 142×18 |
| **wood** (дерево) | стовпи, дошки, цегла бункера | стовпи: 34×70, 24×56 · дошки: 180×16, 102×14, 48×12 · цеглини: 46×26 |
| **box** (картон/ящик) | легкі руйнівні ящики | 50×34, 46×28, 32×32, 28×28, 26×26 |

Нові блупринти додаватимуться — тому текстури мають витримувати довільні
розміри в цих діапазонах.

### 3.2 Що саме малювати

На кожен матеріал — **базова текстура-тайл, що безшовно повторюється по
горизонталі й вертикалі**, + рамка-край. Гра рендерить блок як прямокутник
із заливкою тайлом і обводкою.

| Файл | Розмір тайла (експорт 2×) | Вигляд |
|---|---|---|
| `block-stone.png` | 64×64 (128×128) | сіра кам'яна кладка/бетон |
| `block-wood.png` | 64×64 (128×128) | дерев'яні волокна, теплий коричневий |
| `block-box.png` | 64×64 (128×128) | картонний ящик: скотч, штамп «🐟» абощо |

Додатково для дерева, бо стовпи вертикальні, а дошки горизонтальні:
`block-wood-v.png` (волокна вертикально) — або один тайл, який гра повертає.

### 3.3 Стани пошкодження (обов'язково)

Гра має 3 стани міцності блока: **цілий → пошкоджений (<70% HP) → критичний
(<35% HP) → знищений (розліт уламків)**. Потрібно:

- `cracks-light.png`, `cracks-heavy.png` — **накладні декалі тріщин** 64×64
  (128×128), білі/чорні з альфою, універсальні для всіх матеріалів
  (гра накладає поверх тайла і тонує);
- `debris-stone.png`, `debris-wood.png`, `debris-box.png` — по **4 уламки**
  в одному файлі (сітка 2×2, кадр 16×16 лог. px / 32×32 експорт) — розлітаються
  при знищенні блока.

## 9. Пріоритети і обсяг

**P1 — мінімум для заміни плейсхолдерів (гра виглядає як продукт):**
1. 8 персонажів × 4 анімації (розділ 2) — найбільший обсяг;
2. 3 тайли блоків + 2 декалі тріщин + 3 файли уламків (розділ 3);
3. фон + земля карти 1 (розділи 4.1–4.2);
4. 8 спрайтів снарядів + 6 SVG-іконок зброї (розділ 5);
5. логотип + 2 емблеми (розділ 6; прев'ю структур — процедурні, див. примітку там);
6. шрифт із кирилицею (розділ 7).

**P2 — полірування:** victory/fall анімації, декор двору, SVG контролера
(до того живуть емодзі), FX-текстури частинок (зараз малюються кодом і
виглядають прийнятно), звук, карти 2–3.

**Здача:** файли за структурою з розділу 1 + один прев'ю-лист (все на одному
аркуші) для звірки масштабів. Перед відмальовкою всього — **1 персонаж +
1 структура як пілот** на затвердження стилю.
