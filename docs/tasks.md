# План рефакторингу catz-game-v2

Мета: прибрати костилі й підготувати кодову базу до окремого етапу тюнінгу/перепису
фізики. Поведінка гри при рефакторингу НЕ змінюється (крім явно позначених fix-задач).

**Поза скоупом цього плану:** баланс і перепис фізики (радіуси вибуху, гравітація,
Δv-шкода) — це окрема домовлена фаза після рефакторингу.

## Правила виконання

- Виконуємо **одну задачу за раз**, зверху вниз (залежності вказані).
- Після кожної задачі:
  1. `npm run typecheck` — без помилок;
  2. `npm test` — зелений (з'являється після T2);
  3. ручний прогін: `npm run dev` → `http://localhost:5173/?kb=1` — повний цикл
     меню → бій → перемога → реванш працює;
  4. коміт з номером задачі (напр. `T3: єдиний модуль балістики`);
  5. позначити задачу `[x]` у цьому файлі.
- Якщо задача розкриває проблему поза своїм скоупом — дописати нову задачу в кінець
  відповідної фази, не роздувати поточну.

Всі шляхи нижче — відносно `catz-game-v2/`.

### [x] T7. Явна політика нічиєї (рішення Каріни, 2026-07-11)
`GameScene.endMatch`: «якщо мертві обидві команди — перемагають dogs» (артефакт
порядку перевірок).

**Затверджене правило:** при взаємознищенні стрілець ПРОГРАЄ — окрім випадку,
коли це була влучна атака «все або нічого»: тоді стрілець виграє.

**Механіка критерію влучності (пропозиція, уточнити при реалізації):**
«прямий постріл» = перший контакт снаряда (або кластерного осколка) —
фізично ВОРОЖИЙ ПЕРСОНАЖ, а не земля/блок. Тоді:
- обидві команди мертві + смертельний снаряд прямо влучив у ворога →
  **стрілець виграє** (снайперський "all-in" винагороджується + банер
  «ВСЕ АБО НІЧОГО!»);
- обидві команди мертві від сплешу/обвалу/самопідриву → **стрілець програє**
  (самогубство не перемога).
- Fishing Bomb прямою не буває (вибух — з мініігри, не з контакту) — її
  точність і так компенсована корекцією ±120 px.
- Реалізація: `ProjectileEntity` запам'ятовує ціль першого контакту;
  резолюція кінця матчу дивиться на прапорець. Чиста функція + тести на
  обидва сценарії.
- **Готово, коли:** обидва взаємознищення детерміновані, покриті тестом,
  банер відрізняє героїчну перемогу від програшу.

## Фаза 2 — розбиття GameScene (найбільша фаза)

GameScene зараз — god object на 441 рядок: стейт-машина, ввід, шкода, фішинг,
кластери. Розбиваємо по одному шматку за задачу; після кожної — сцена лише
композиція систем.

### [ ] T8. TurnStateMachine
- Новий `src/screen/systems/TurnStateMachine.ts`: стани
  `settling | aiming | flying | fishing | resolving | ended` з явними методами
  переходів і власними таймерами (turn deadline, settle min/max).
- Прибрати магічні числа з `update` (1200мс — у конфіг як `SETTLE_MIN_MS`).
- **Убити головний хак:** `resolveFish` більше не ставить `settleStart` у
  майбутнє (`time.now + 400`) — замість цього окремий стан `resolving`, перехід
  із якого відбувається колбеком після вибуху, а не таймінгом tween-анімації.
- GameScene.update лише делегує в машину.
- Тест: послідовність переходів aiming→flying→settling→aiming; таймаут ходу.
- **Готово, коли:** фішинг-бомба (перевірити в `?kb=1` за fisher/terrier)

### [ ] T10. FishingSystem

## Фаза 3 — мультиплеєр і стійкість мережі

### [ ] T13. 2–6 гравців, максимум 3 на команду (вимога Каріни, 2026-07-11)
Зараз `PlayerHub` робить команду ексклюзивною — максимум 2 гравці.

**Модель (ухвалена Каріною, 2026-07-11): персонажі НЕ «чиїсь» — дві
незалежні ротації.** Ростер команди завжди 4 персонажі (сила команди не
залежить від кількості гравців — нерівні склади 1v3 чесні):
- ротація персонажів: кіт → пес → кіт → …, мертві пропускаються. ⚠️ При
  переписі виправити квірк поточної ring-черги (задокументований тестом T2):
  після смерті персонажа команда може отримати два ходи поспіль — має бути
  строге чергування команд (хід команди → її наступний живий персонаж);
- ротація гравців усередині команди: коли настає хід команди, наступний
  живий персонаж дістається НАСТУПНОМУ гравцю команди по колу.
- Приклад (3 гравці, 4 персонажі): P1+C1, P2+C2, P3+C3, P1+C4, P2+C1, … —
  всі гравці ходять порівну незалежно від кількості персонажів, персонажі
  використовуються порівну незалежно від кількості гравців.
- Disconnect стає тривіальним: гравець просто випадає з ротації, нічого
  перепризначати (деталі в T14).

Обсяг:
- `PlayerHub`: команда = список гравців, ліміт 3; при переповненні —
  відмова з причиною `full`; 7-й+ девайс — глядач (екран «команди повні»
  на контролері).
- `TurnSystem`: додається ротація гравців per team; пара «персонаж+гравець»
  формується на початку ходу. `your_turn` надсилається гравцю цього ходу
  (`hub.send(playerId, …)`); `aim/fire/weapon/tap` приймаються лише від нього.
- Протокол: `lobby` → списки імен по командах + прапорці заповненості;
  `team_denied` з причиною; екран глядача. (Типи в `shared/protocol.ts`.)
- MenuScene: до 3 імен на команду; старт за ≥1 гравця в кожній команді
  (разом 2–6). HUD/банер ходу: «Fluffy (Оля)».
- Нік гравця — з профілю AirConsole (`getNickname`), fallback «Player N»
  (WS/kb-режими).
- У лобі до старту можна перестрибувати між командами (якщо є місце).
- Підключення ПОСЕРЕД бою → глядач до кінця матчу, вступає в команду з
  наступного матчу/реваншу.
- Голосування вже готове до кількох голосів на команду — без змін.
- Реванш зберігає склад команд; ротації стартують заново.
- Тести: послідовність пар для 1/2/3 гравців × 4 персонажі; маршрутизація
  your_turn; відмова 4-му гравцю; продовження ротації після disconnect.
- **Готово, коли:** `?local=1` з 3 вкладками в одній команді — телефони
  отримують ходи по колу, приціл рухає лише гравець поточного ходу;
  7-ма вкладка бачить екран глядача.

### [ ] T14. Обробка disconnect (потребує T13)
- Завдяки моделі без власності (T13) перепризначень немає: гравець, що
  відпав, просто випадає з ротації, решта команди продовжує по колу.
- Єдиний особливий випадок — ВСІ телефони команди відпали: її ходи
  скіпаються з банером (гра не висить); реконект повертає гравця в ротацію.
- GameScene: якщо відпав гравець, чий зараз хід — банер і скіп ходу через 3с
  (не 25с мертвого чекання).
- VoteScene: `every()` на порожній команді зараз миттєво фіналізує голосування —
  чекати таймер, якщо хоч одна команда без гравців-голосуючих... (у соло-режимі
  VoteScene і так не запускається).
- MenuScene: якщо всі відпали — повернутися в стан «Очікування гравців».
- **Готово, коли:** закриття вкладки контролера в кожній сцені не ламає гру
  (перевірити `?local=1` із двома вкладками-«телефонами»).
